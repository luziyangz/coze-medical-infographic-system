# 医疗科普图文系统：从主题到系列图片

本仓库另提供一套可安装到 Codex、WorkBuddy 等智能体中的[独立 Skill](Skill安装与使用.md)。工作流与 Skill 是两套：下文说明 Coze 实现；Skill 由当前智能体执行，不会自动接通 Coze。

在Coze中，这套系统把内容制作拆成八个可以协作的工作流：从理解用户想做什么开始，经过选题与医学研究，最后完成文案、分镜、图片和飞书归档。

这份文档面向想了解系统、使用系统，或借鉴它搭建其他业务流程的读者。可以从[图文展示版](展示.html)完整阅读，也可以按下面的主题选择章节。

## 先看整体

![系统整体业务流程示意](assets/diagrams/system-flow.svg)

系统中有两层组织：**主对话管理人与任务的沟通，图文创作主线管理一次内容生产。** 意图收集、痛点分析和医学研究为创作准备输入；Script、Graphic和Delivery把输入依次转成文案分镜、图片和保存结果。

| 层次 | 工作流 | 作用 |
|---|---|---|
| 对话与任务 | 科普主对话 | 理解本轮反馈，记录阶段和已确认的信息，安排下一步 |
| 内容准备 | 意图收集、痛点分析、医学研究 | 明确要做什么、讲哪个问题、依据什么讲 |
| 生产调度 | 图文创作主线 | 串联脚本、图像和保存三个模块 |
| 内容生产 | Script、Graphic、Delivery | 形成文字、页面图片及飞书内容记录 |

## 用一个例子理解

用户提出：“我想做儿童鼻炎科普，主要给家长看。”

系统先把这句话整理成需求，继续了解这次想讲的具体内容。需求明确后，痛点分析提供可选的切入点；用户选择后，医学研究形成内容依据与目标。再确认平台、受众版本、形式、风格和比例，图文主线便可以按这些要求组织制作。

“儿童鼻炎”始终是科普方向，某次选择的具体问题是本次选题。“换一个切入点”保留原方向，“改成水彩”调整制作表达，“重新做儿童睡眠”才进入另一项主题任务。

## 这套做法还能用在哪里

只需要整理用户需求时，可以借鉴“新消息+历史需求→提取与补问→统一结果”的意图收集结构；已经有分镜时，可以独立使用Graphic；已经有图文时，可以独立使用Delivery。

拓展到新领域时，可以把医疗需求字段换成课程、教程或培训字段，把医学资料与角色库换成该领域的知识和视觉资产，沿用分阶段确认、模块交接和系列制作的组织方法。具体案例见[模块复用与拓展](05-模块复用与拓展.md)。
