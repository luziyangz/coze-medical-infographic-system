# 使用说明

本页说明 **Coze 工作流方案**的阅读、搭建与使用。若要让 Codex、WorkBuddy 等智能体执行科普创作，请阅读[Skill 安装与使用](Skill安装与使用.md)。两套方案分别运行，安装 Skill 不会替你导入或连接 Coze 工作流。

Coze 部分未附可直接导入的工作流导出包；`tools/`用于文档生成、发布检查和技能打包，`skills/`内另有独立技能及可选项目脚本。

## 1. 阅读文档

可以直接阅读GitHub首页README，再进入各章节。也可以从Code菜单选择Download ZIP，解压后双击`docs/展示.html`，离线查看完整图文版。

使用Git下载：

```bash
git clone https://github.com/luziyangz/coze-medical-infographic-system.git
cd coze-medical-infographic-system
```

这是公开仓库，阅读与下载不需要作者的账号权限。

| 想做什么 | 建议阅读顺序 |
|---|---|
| 了解系统 | 系统总览 → 工作流职责与组合 |
| 使用一项科普任务 | 整体流程与SOP → 图文效果与应用案例 |
| 了解视觉和飞书 | 图文生成与飞书协作 |
| 单独使用模块或迁移领域 | 模块复用与拓展 |

## 2. 修改文档并更新图文版

普通阅读不需要安装Python依赖。需要更新HTML时，使用Python 3.10或以上版本，并在仓库根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe tools/render_docs.py
.\.venv\Scripts\python.exe tools/check_release.py
```

macOS/Linux使用对应虚拟环境命令：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python tools/render_docs.py
.venv/bin/python tools/check_release.py
```

编辑`docs/`中的Markdown，替换或增加`docs/assets/`中的素材，重新运行生成脚本即可。HTML使用本地图片和样式文件，没有外部字体或脚本依赖。

## 3. 在自己的Coze空间组织工作流

先按[工作流职责与组合](02-工作流职责与组合.md)准备八个模块，再在调用节点中选择自己空间内的工作流。

| 层次 | 需要准备的模块 | 主要交接内容 |
|---|---|---|
| 用户沟通 | 科普主对话 | 当前阶段、用户消息、已确认需求与反馈 |
| 内容准备 | 意图收集、痛点分析、医学研究 | 需求、候选及已选问题、医学目标 |
| 制作调度 | 图文创作主线 | 本次选题与内容准备结果 |
| 制作与归档 | Script、Graphic、Delivery | 文案分镜、图片结果、飞书保存反馈 |

准备会话保存位置，用来记录需求、当前阶段、候选列表、已选痛点、医学目标、制作参数及内容结果。候选列表和单个已选对象分别管理，需求业务字段统一放在`intent_info.data`内。

### 图文模块输入约定

| 模块 | 输入 | 输出 |
|---|---|---|
| Script | `final_selected_theme`、`intent_info`、`pain_points`、`target_card` | `script_result` |
| Graphic | `script_result` | `render_result` |
| Delivery | `script_result`、`render_result` | `delivery_result` |

将上游节点输出真实引用到下游输入。Script、Graphic、Delivery之间传递固定结构的JSON文本；给用户的回复使用自然语言和图片。

如果从自己已有的Coze导出包开始，在自己空间导入后重新核对调用目标、输入输出、知识库、插件与飞书表。按依赖关系准备制作子流程、图文主线和主对话，再从关联智能体的对话入口使用。

## 4. 准备自己的飞书数据

按用途组织以下数据：

| 数据 | 内容示例 | 使用模块 |
|---|---|---|
| 平台规则 | 平台名称及表达要求 | Script |
| 人物资产 | 主角、科普角色及参考图片 | Graphic |
| 辅助资产 | 疾病形象、器官示意等 | Graphic |
| 风格资产 | 风格说明与参考图片 | Graphic |
| 布局资产 | 页面布局要求与模板 | Graphic |
| 页面结果 | 主题、批次、页码、文字、图片附件及页面信息 | Delivery |

这些是业务分组，实际列名、类型和枚举需要与自己的工作流映射一致。图片列使用飞书附件类型：将图片上传后取得附件标识，再写入页面记录。

配置自己的应用认证和表格访问方式。仓库提供的[配置模板](../config/README.md)用于记录应当配置的位置，不会自动连接作者账号。

## 5. 开始一项内容任务

在关联智能体的对话入口描述需求，例如：

> 我想做一组给家长看的儿童鼻炎科普，先帮我整理适合讲的具体问题。

按系统追问补充读者与内容范围，选择一个具体选题，阅读并确认医学目标，再确认受众版本、平台、形式、风格和比例。随后由Script、Graphic、Delivery依次制作与整理。

需要调整时，说明是更换具体问题、修改风格、改变受众，还是重新开始另一主题。完整操作逻辑见[操作SOP](01-操作SOP.md)。

## 6. 单独使用模块

- 只整理需求：调用意图收集，保存结果，下一轮继续传入历史需求。
- 只制作文字：准备有效需求、选题和医学目标，调用Script获取文案与分镜。
- 已有脚本包：调用Graphic，按既定分镜制作系列图片。
- 已有脚本与图片结果：调用Delivery，整理飞书附件与页面记录。

迁移到课程、产品教程或培训图卡时，同步调整需求字段、内容依据、表达规则和视觉资产。具体例子见[模块复用与拓展](05-模块复用与拓展.md)。

## 7. 配置与隐私

仓库中的`.env.example`和`config/connections.example.json`使用占位值。实际配置保存在本地被忽略的`.env`或`config/local.json`，并在自己的Coze连接中填写。

不要将真实密钥、应用标识、表格标识、私有工作流链接、原始认证导出包或调试记录加入提交。替换工作流截图时，检查地址栏、节点详情、输入值和图片元数据。

## 8. 后续同步修改

在这个独立文档仓库中修改并生成HTML，检查通过后同步：

```bash
python tools/check_release.py
git status --short
git add README.md docs tools config skills tests requirements.txt .env.example .gitignore .gitattributes
git diff --cached --stat
git commit -m "Update documentation"
git push
```

提交前查看暂存区文件列表，确认个人配置没有进入提交。检查脚本负责常见文本标识和文件引用检查，新增图片仍需人工查看内容。
