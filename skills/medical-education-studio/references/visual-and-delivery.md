# 视觉制作与交付

## 先判断可完成的产物

| 当前能力 | 可完成的结果 |
|---|---|
| 文本与文件工具 | 全局视觉方案、逐页提示词、锁定文字、布局与人工制作清单 |
| 再有图像生成工具 | 实际候选图片及逐页输出清单 |
| 再有图像查看、OCR或其他检查工具 | 对真实候选的文字与画面复核；不足之处留待人工检查 |
| 再有用户自己的飞书连接 | 读取授权资产、上传附件和写入页面记录，具体操作取决于连接能力 |

工具需要在当前宿主中实际可调用；不要假设 Codex、WorkBuddy 或其他智能体安装本 Skill 后就带有同一组模型、搜索和飞书插件。优先遵循宿主的图像工具和连接使用规范。

## 组织多页视觉

1. 读取已确认文案、分镜、风格、比例与参考图。先在 `04-visual-plan.md` 写全局设定：配色、材质、人物外观、字体与文字区、页间节奏。
2. 有现成风格资产时使用已授权参考；没有时先写统一风格规范，必要时用当前图像工具生成并确认风格或角色参考。参考图真的存在后才登记到项目资产中。
3. 锁定跨页人物的外观、服装、年龄范围与角色关系。医学器官、疾病拟人形象和过程示意同样需要有明确含义，避免暗示未经支持的机制。
4. 为每页写生成指令，包含页面任务、锁定文字、场景、角色参考、布局、风格和比例。使用稳定页码，保留文字修订与图片版本的对应关系。
5. 用户请求出图且工具可用时真正生成；保存返回的可用文件或工具产物链接。没有图像工具时输出上述制作包，保留 `visual.status = planned`。

3D卡通、手绘水彩、写实插画是可选风格方向，不意味着本包包含这些风格的模型或资产。原仓库中的 Coze 截图和六页候选样张是工作流案例，不能用来证明当前 Skill 已经运行成功。

## 复核与定向修改

查看实际候选，检查文字是否完整正确、人物是否一致、视觉是否与文字表达同一含义、布局是否适合阅读。无法读取图中文字时不能标为检查通过。复核状态为 `pending`、`passed` 或 `needs_fix`。

已有至少一张真实候选图，`visual.status` 可记为 `generated`；按页报告候选数量、待复核、需修复与缺页。只有提示词、空文件或未返回结果的调用不算候选图。

对具体问题进行定向修复，复用仍合适的参考和文案。每次额外生图都应与用户已要求的任务范围一致；宿主有成本限制时遵循实际限制。保留已成功页面，不因一页失败重跑整批。

## 本地归档

在独立项目目录保留 `project.json`、本轮实际形成的 Markdown 与 `images/`。在 `05-delivery.md` 中列明每页文字、实际图片位置、复核状态和仍待完成的事。只产出文案时不写“图片已生成”。

## 使用者自己的飞书

用户提出保存请求后，优先使用宿主已有飞书连接；没有连接时可说明需要在其环境配置，先完成本地归档。不要在 Skill 内保存真实 App ID、密钥、访问令牌或私有表格地址。

若当前任务已授权读取资产，按实际表结构获取平台规则、风格、人物和布局。若当前任务已授权写入指定表：

- 先读取目标表结构，明确主题、项目、页码、正文、附件与复核状态的字段映射。字段名与枚举以目标表实际定义为准。
- 若连接直接支持附件上传，使用该能力；若使用飞书开放平台 API，先查当前官方文档，按权限和正确的附件归属上传，取得返回的 `file_token` 后再写附件字段。普通图片 URL 不能冒充已上传附件。
- 将每页文字、附件与状态写入对应记录。记录真实返回的记录标识或链接；能够读取时回读核对。
- 用项目标识与页码查找已存在记录后再补写。部分成功时保存成功项、标注失败项，避免重试整批造成重复。

`delivery.target` 只在实际使用飞书时设为 `feishu`。`saved` 需要本次应保存页面的成功记录；不满足时使用 `partial`、`failed` 或 `not_started`，不能凭本地清单声称飞书保存成功。
