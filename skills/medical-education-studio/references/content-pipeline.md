# 需求、选题、研究与文案

## 需求收集可以单独使用

从本轮消息合并已有需求，输出一份简报与最必要的补充问题。用户已经提供的方向、读者、场景不重复询问。不要把“暂未确定风格”误当作不能讨论选题。

| 信息 | 用途 |
|---|---|
| 科普方向 | 研究的健康内容范围 |
| 读者、年龄和阅读情境 | 解释深度、场景、儿童与家长表达 |
| 具体困扰 | 把大方向收敛成可讲清楚的问题 |
| 产物、平台与形式 | 决定交付是需求简报、文案、图卡或完整制作 |
| 风格、比例、页数、已有资产 | 安排视觉生产与工作量 |

“给六岁孩子的家长看”属于家长表达；“六岁孩子自己读”需要儿童表达；亲子共读可采用孩子提问、家长回应。避免仅凭出现孩子年龄就误选儿童版。

未确定的字段保存为 `null`，不要把推荐值悄悄改成用户已确认值。可以提议默认方案，并说明它是本轮采用的策划假设。

## 从方向到具体选题

围绕读者情境给出少量、有区分度的候选，通常三至五个足够。每个候选说明具体问题、读者价值、内容角度和已知依据；不要仅换标题措辞。

检索到的真实咨询、官方问答与可引用资料可以支持选题。无法检索时可以做策划，但标为“策划候选，尚未进行需求热度验证”；不使用“最热门”“家长最关心”等无证据判断。

让候选各有稳定 `topic_id`。用户说“第二个”时据当前候选匹配；歧义或无效序号先解释，不修改选中对象。明确选择后立即进入该选题的研究，不要求额外回复“继续”。

成功换出新候选列表才增加 `successful_rerecommendations`。解释候选、失败重试、无效序号不增加次数。同方向累计成功重推荐达到五轮后，只有获得具体偏好才再推荐；计数始终保留。

## 形成可创作的证据卡

优先阅读公共卫生机构、专业指南、专业学会、系统综述和相关原始研究。按当前题目核对更新时间、适用年龄、人群与地区；不能只看搜索摘要。用户提供的资料可以作为来源，但要明确资料类型和可核验程度。

记录每个来源的标题、链接或本地文件、访问日期；逐条记录内容主张对应哪些来源、支持的范围和限制。对因果、频率、疗效、诊断或治疗比较尤其核对原文。来源冲突时保留差异，缩小表达范围，不将不确定性改写为定论。

证据卡应回答：这套内容要帮助读者理解什么、可以怎么讲、不能推到哪些人群或情境。内容面向大众科普；不要据此为具体个人诊断、推荐处方或生成未经支持的剂量建议。

| 状态 | 含义与下一步 |
|---|---|
| `ready` | 已读来源支持本次拟用主张，可进入创作 |
| `limited` | 有可用依据但范围有限，列出限制，用户同意后在范围内创作 |
| `unverified` | 没有可核验依据，仅能给出待核实提纲或继续收集资料 |
| `failed` | 工具调用、网页读取或结构处理失败，保留已有资料并说明需要恢复的步骤 |

`limited` 仍需要真实来源。完全没有来源时不能通过用户“确认继续”变成可验证医学内容。

## 从证据卡到文案和分镜

先明确读者最后应理解或能采取的行动，再安排内容顺序。可采用“困惑—解释—情境—行动—总结”，也可用问答、漫画或故事；按题目需要调整。

文案锁定后逐页规划。每页至少记录：稳定 `page_id`、标题、页面文字、画面任务、支撑医学主张的 `claim_ids`。封面等无医学主张的页面可以使用空引用列表。引用列表不能代替在研究材料中留下实际依据。

压缩文字时保留限制条件、时间、人群与否定词。图中箭头、表情、对比色和角色对白同样可能暗示医学结论，需与证据卡一致。

默认交付需求简报、证据与文案文件，以及项目状态；用户只要其中一项时交付对应项。文件使用 [project-state.md](project-state.md) 中约定的名称，正文对读者保持自然语言。
